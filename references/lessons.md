# 九条原则和八条教训

66 种问题，大致可以归到九条原则。八条教训是方法本身踩过的坑。

## 九条原则

1. **以第一次读的人为准。** 读者读到哪里要停下、要读两遍，哪里就有问题。（P1–P13、P45–P47）
2. **读者只拥有前面读过的东西。** 先定义再使用，只建立在前文之上，指代的东西就在附近，结果不在方法之前出现，引言从空白一步步推到方法。（P6、P7、P20、P21、P31、P35–P37、P44）
3. **一个名字只指一样东西，一样东西只用一个名字。** 改名时要查新名字有没有撞上文中已有的术语；两样东西也不能合用一个名字。（P12、P14–P17、P22、P23）
4. **说到证据为止。** 每个数字能从数据重现，每个引用能在原文找到，每个结论不比结果说得宽、说得强；也不因为怕说过头而少说。（P25–P33）
5. **只讲研究本身，不讲文章是怎么写成的。**（P42、P43）
6. **一句话做一件事，一段话讲一个主张，一种内容只有一个家。**（P2、P3、P34、P39、P41）
7. **用作者自己和这个领域的语言。** 不自造词，不用作者不会用的词，借来的术语只用它原来的意思，能用常用词就不用生僻词，保留作者自己的推理。（P13、P18、P19、P21、P22、P24、P64）
8. **形式服从阅读。** 图注、坐标轴、字号、粗体、斜体、引号和分页，都是为了让读者读得顺；不为了好看或排版去改内容。（P48–P56）
9. **读着像机器写的，多半是几种小习惯凑在一起。** 对比句式、冒号、破折号、整齐的句长和排比、空洞的过渡和段尾总结、附近重复的发现、格言和比喻，单看一处都不算错。（P57–P63）

## 八条教训

1. **抽象要到能检查的程度，又不能只按字面查。** 只按字面查，会漏掉同一类的其他写法；抽象得太粗，又会把两样东西合成一个名字。
2. **脚本负责找全，判断要靠读。** 对比句式只减了一部分，因为表达局限、不显著结果和文献空白的否定句承载内容；缩写检查标出 13 处，真有问题的只有 3 处；没有校准过的模型评判，结论只作参考。
3. **每一种检查都有盲区。** `lay in` 经过大约十二轮检查都没被发现，因为没有一个检查专门找它。按审阅意见新写的两句，仍然只写了比较的一边，过了两天才补上。所以脚本之外，还要有一遍不带清单、从头读到尾的通读。
4. **每次修改都可能制造下一个问题（Each fix can create the next problem）。** 为回应一条意见加进去的一句，后来成了段落衔接的问题；为解决一个词的撞车新写的句子，三天后成了镜像句；缩短图注删掉了读者需要的说明；拆句拆出了连续三句都以 The 开头；benchmark 改名 threshold 后又撞上另一个意思；别处的修改让摘要悄悄超过了字数上限；我否定过的 `lies in` 被写了回来；为说清 this question 指什么，又把意思改窄了；我专门要求改掉的 `the name`，又出现在重写的句子里。所以每次修改后都重读这一段和前一段，并重跑全套检查。
5. **规则之间会打架。** 按范文把讨论部分的标题改成结论句，五天后又按「标题写内容」改回来；「段尾不写空洞总结」删去了按导师意见加的一句；ASD-STE100 的大部分规则让文字更不像人写的，最后只采用了一条。两条规则撞在同一句上时，回头看前一条规则当初为什么要写这句话。
6. **外部意见先核对，再采用。** 人的意见和模型的意见一样，先用原文和数据核对，成立的才改，不成立的写明理由。
7. **冻结的内容不动。** 研究问题的措辞、引文的原文、没有数据依据的数字、作者自己的反思段落，每一轮都列为冻结，只报告，不修改。
8. **留下痕迹，任何修改都能撤回。** 每一处修改都有修改前的原文、备份和日志，所以可以放心地大范围修改，也可以只撤回其中一处。
